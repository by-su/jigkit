# 설계: 체크아웃 이탈 줄이기

입력: `docs/prd/checkout.md`. 무엇을 만들지는 PRD가 정했다. 여기서는 **어느 화면에서 어떤 상태로 보이는지**만 정한다.

PRD의 순서(기준 1 → 기준 2·3)를 화면에도 그대로 반영한다: **계측(S2)이 먼저 살아 있어야 개선(S1)의 방향이 결정된다.** 설계는 S1의 개선 *방향*을 정하지 않고, 방향이 정해졌을 때 갈아끼울 자리만 만든다 `[J]`.

## 화면 목록

| ID | 화면 | 역할 |
|---|---|---|
| S1 | 카드 정보 입력 | 개선 대상 화면 (이탈의 62%) |
| S2 | 필드별 이탈 대시보드 | 기준 1을 확인하는 곳 |
| S3 | 결제 진입점 (회원/게스트 분기) | A/B 테스트 분기가 사용자에게 보이는 유일한 지점 |
| S4 | A/B 결과 리포트 | 기준 4를 확인하는 곳 |

---

## 정상 경로 (먼저 하나 끝까지)

1. 사용자가 배송지까지 마치고 **S3** 진입 → 배정된 분기(회원 / 게스트)에 따라 진입 방식이 갈린다.
2. **S1** 진입 → 카드번호 · 유효기간 · CVC · (필요 시) 할부 입력.
3. 각 필드에서 `focus / blur / error / abandon` 이벤트가 발생 → **S2**에 필드 단위로 쌓인다.
4. 제출 → 승인 대기 → 완료.
5. 4주 뒤 **S2**에서 기준 2·3, **S4**에서 기준 4를 읽는다.

---

## S1 — 카드 정보 입력

| 상태 | 정의 |
|---|---|
| 빈 상태 | 필드 전부 비어 있음. **오류 메시지는 이 시점에 하나도 표시하지 않는다.** 제출 버튼은 보이되 비활성. |
| 로딩 | (a) 화면 진입 시 결제수단/할부 옵션 조회 — 스켈레톤, 입력 필드는 그 전에 먼저 활성화한다. (b) 제출 후 승인 대기 — 화면 전체 잠금, 취소 불가, 중복 제출 차단. |
| 에러 | ① 필드 단위 검증 실패 → 해당 필드 아래, **blur 시점에만** 표시. 입력 중에는 표시하지 않는다. ② 승인 거절 → 화면 상단, **입력값은 유지**한 채 재시도 가능. ③ 네트워크/타임아웃 → "결제가 완료됐는지 불확실" 문구 + 주문 조회 경로 안내. 자동 재시도 없음. |
| 경계값 | 카드번호 14~19자리(브랜드별), 유효기간 = 당월 이상 · +20년 이하, CVC 3~4자리, 할부 옵션 0개일 때 필드 자체를 숨김, 승인 대기 30초 초과 시 에러 ③으로 전환. |

이탈 이벤트: 필드 focus 후 **완성 없이** 화면을 떠나면 그 필드의 `abandon`. 어느 필드에도 focus하지 않고 떠나면 `abandon(none)` — 이 값이 PRD의 "신뢰 문제 vs 입력 부담"을 가르는 신호다.

## S2 — 필드별 이탈 대시보드

| 상태 | 정의 |
|---|---|
| 빈 상태 | 수집 시작 전 / 기간 내 세션 0건. **0%로 그리지 않고** "데이터 없음 + 수집 시작일"을 명시한다. |
| 로딩 | 기간 집계 중 — 스켈레톤. 부분 로드된 구간을 먼저 보여주지 않는다(잘못 읽힘). |
| 에러 | 집계 실패 → 마지막 성공 시각과 함께 실패 표시. **직전 성공 데이터를 최신인 것처럼 보여주지 않는다.** |
| 경계값 | 세션 100건 미만 구간은 비율 대신 원시 건수만 표기. 필드별 합이 화면 이탈 총계와 ±1%p 넘게 어긋나면 불일치 배지를 띄운다(기준 1의 "합산되어 설명됨"이 깨진 상태). |

## S3 — 결제 진입점 (A/B 분기)

| 상태 | 정의 |
|---|---|
| 빈 상태 | 장바구니 비어 있음 → 결제 진입 자체를 막고 장바구니로 되돌림. |
| 로딩 | 분기 배정 조회 — **배정 전에는 어느 쪽 UI도 그리지 않는다.** 깜빡임(회원 → 게스트 전환)은 그 자체로 이탈 요인. |
| 에러 | 배정 조회 실패 → **대조군(회원 결제)으로 고정**하고, 해당 세션은 실험에서 제외 표시. |
| 경계값 | 한 세션 내 재진입 시 배정 유지(재배정 금지). 이미 로그인된 사용자는 실험 대상에서 제외. |

## S4 — A/B 결과 리포트

| 상태 | 정의 |
|---|---|
| 빈 상태 | 테스트 미시작 / 표본 부족 — "판정 불가"로 표시. |
| 로딩 | 집계 중 스켈레톤. |
| 에러 | 집계 실패 시 수치 자체를 감춘다. |
| 경계값 | **완주 전에는 결론 문구를 렌더하지 않는다.** 표시 단위는 항상 `차이값 + 신뢰구간`이며, "개선됨" 같은 서술형 판정 문구는 화면에 넣지 않는다(PRD 기준 4의 통과 조건). |

---

## 성공 기준 ↔ 화면 연결

| PRD 기준 | 확인 화면 | 화면에서 무엇을 보면 통과인가 |
|---|---|---|
| 1 필드 단위 분해 | S2 | 필드별 `focus/error/abandon`이 모두 표에 있고, 필드별 합 = 화면 이탈 총계(불일치 배지 없음) |
| 2 전체 이탈 38%→30% | S2 (단계별 뷰) | 배포 전 4주 / 후 4주를 같은 기준으로 나란히, 두 구간 모두 표본 충족 상태 |
| 3 카드 화면 비중 62%→50% | S2 (단계별 분포) | 위와 같은 두 구간의 분포 비교 |
| 4 게스트 결제 효과 수치화 | S4 | 완주 배지 + 완료율 차이 + 신뢰구간이 실제 값으로 표시 |

기준 2·3은 **S2가 기준 1을 통과한 뒤**의 데이터로만 읽는다. 통과 전 구간은 S2에서 "기준 1 미충족" 배지를 달아 비교 대상에서 뺀다.

---

## 구현에 맡기는 것 / 맡기지 않는 것

**맡긴다 (구현이 정해도 된다)**
- 이벤트 수집을 기존 파이프라인에 얹을지 분리할지, 전송 방식·배치 주기 (PRD "구현 메모").
- A/B 분기가 진입점에서 끝나는지 주문 데이터 모델까지 가는지, S1 개선이 프론트 단독인지 결제 API를 부르는지.
- 대시보드 구현 형태(자체 화면 / 기존 BI 도구), 차트 종류, 필드 입력 위젯 형태(분할 입력 여부).
- 카드 브랜드 판별 방식, 스켈레톤의 시각적 형태.

**맡기지 않는다 (여기서 정했고 바꾸려면 되돌아와야 한다)**
- 빈 상태에서 오류를 표시하지 않는다 / 오류는 blur 시점에만.
- 승인 거절 시 입력값 유지, 타임아웃 시 자동 재시도 없음.
- `abandon(none)`을 별도 이벤트로 구분해 수집한다 (PRD의 미결 질문이 여기서 갈린다).
- S3 배정 실패 시 대조군 고정 + 실험 제외.
- S4는 완주 전 결론 문구를 그리지 않고, 항상 신뢰구간과 함께 표시한다.
- 표본 100건 미만 구간은 비율로 그리지 않는다.
- **S1의 개선 방향(입력 부담 vs 신뢰) 자체는 구현이 정하지 않는다.** 기준 1의 결과로 정한다.

## 앞 단계로 되돌릴 질문 (PRD 수정은 하지 않았다)

1. `[?]` **기준 2·3의 "개선 배포"가 무엇을 가리키는지 PRD에 없다.** 계측(기준 1) 배포도 포함인지, 계측 결과로 정해질 S1 개선 배포만인지에 따라 "배포 전 4주"의 기준선이 달라진다. → 기준선 시점 정의 필요.
2. `[?]` **A/B 테스트 완주 조건이 없다.** 표본 크기 / 기간 / 최소 검출 효과 중 무엇으로 완주를 판정하는지 정해지지 않으면 S4가 "판정 불가"에서 벗어나는 시점을 화면이 알 수 없다.
3. `[?]` **A/B 테스트와 S1 개선의 동시 진행 여부.** 둘이 같은 기간에 돌면 기준 2·3의 개선폭에 게스트 결제 효과가 섞인다. 순서를 PRD에서 정해야 한다.
4. `[?]` **게스트 분기에서 카드 입력 화면이 회원과 동일한지.** 다르면 S1의 상태 정의가 두 벌 필요하다.
5. `[?]` 범위에 "결제 수단 추가"는 빠졌는데, 이미 붙어 있는 간편결제 진입점이 S1/S3에 있다면 이탈 계측 대상에 포함되는지 불명.
