# 스택 훅이 몇 번 도는가

`probe/stack-apply/run.sh` · Claude Code 2.1.228 · 2026-08-13

스택 배치가 서 있는 가정은 **"이벤트당 훅 항목 하나 = 확장자에 맞는 도구 하나만 돈다"** 다.
단위 검사는 배치의 *모양*(항목 개수)까지만 본다. 실제 발화 횟수는 여기서 잰다.

## 1. 스택 둘을 한 프로젝트에 겹쳐 넣고 `.py` 하나를 고친다

`jig stack apply python` 다음에 `jig stack apply typescript`, 그리고 Edit 1회.
디스패처의 실행 명령을 마커 기록으로 갈아 끼워 셌다.

| | 결과 |
|---|---|
| `PostToolUse` 항목 수 | **1개** |
| `PreToolUse` 항목 수 | 1개 |
| py 분기 발화 | **1회** |
| ts 분기 발화 | **0회** |

성립한다 `[M]`. 확장자 분기가 디스패처 안에 있으므로 `.py` 편집에 Biome 쪽은 돌지 않는다.

### 여기서 잡힌 실제 버그 — 두 번째 apply 가 첫 번째 분기를 지웠다

처음 측정에서 **py 0회 · ts 0회** 가 나왔다. 원인은 발화가 아니라 배치였다:
`apply` 가 마커 블록을 통째로 갈아 끼워서 `typescript` 적용이 `python` 의 `.py` 분기를
지웠다. 디스패처 파일은 그대로 있고 `settings.json` 항목도 1개라서 **배치 모양만 보는
검사는 전부 초록불이었다** — 조용히 훅이 사라지는 형태다.

`adapters/claude/stack_apply.py:_merge` 가 블록을 **id 로 병합**하도록 고쳤다. 이 실패는
단위 검사로는 안 잡힌다("항목 1개"는 여전히 참이므로) — 회귀는 이 프로브가 잡는다.

## 2. 같은 settings **파일 안**의 동일 command 항목 2개

문서는 "같은 handler 를 여러 settings **파일**에 정의하면 한 번만 돈다" 까지만 말한다 `[D]`.
한 파일 안의 중복은 적혀 있지 않아서 쟀다.

| 항목 | 발화 |
|---|---|
| 동일 command 2개 (한 파일, 같은 matcher) | **1회** |

dedupe 된다 `[M]`. `probe/PENDING.md` 의 해당 `[?]` 는 이것으로 닫혔다.

**그래서 바뀐 판단**: `settings.json` 을 command 문자열로 찾아 교체하는 이유는 이제
"중복 발화를 막기 위해서" 가 아니다 — 중복은 어차피 한 번만 돈다. 이유는 두 가지로 좁혀졌다.
(1) 재적용마다 항목이 늘어나 파일이 읽을 수 없게 되고, (2) 배열에 덧붙이면 사람이 손으로
넣은 다른 훅과 우리 항목을 구별할 수 없다.

## 재현

```bash
./probe/stack-apply/run.sh
```

샌드박스는 `probe/sandbox/stack-apply/` 이고 매 실행마다 지워진다. 실제 도구(ruff·biome)는
깔지 않는다 — 재려는 것이 "몇 번 불렸나" 이고 도구 설치는 그 답을 바꾸지 않는다.
