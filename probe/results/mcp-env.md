# MCP 서버의 기동 비용과 `${VAR}` 확장

`probe/mcp-env/run.sh` · Claude Code 2.1.232 · 2026-08-14

카탈로그(`library/stacks/`)가 MCP 정의를 직접 싣고 프로필이 id 로 켜는 구조는 두 가정 위에
선다. 둘 다 근거가 없어서 쟀다.

1. 커밋되는 카탈로그에 토큰을 값으로 넣을 수 없으니 `${VAR}` 참조를 쓴다 —
   **Claude Code 가 `--mcp-config` 파일 안의 `${VAR}` 를 확장하는가?**
2. "MCP 를 켜면 도구 정의가 컨텍스트를 먹는다" 는 판단이 여러 `why` 에 `[J]` 로 박혀
   있다 — **얼마나 먹는가?**

## 1. 기동 토큰

같은 디렉터리·같은 settings 에서 `--mcp-config` 만 바꿔 `-p "hi"` 를 돌리고
`input_tokens + cache_read + cache_creation` 을 합산했다. 캐시 상태에 흔들리므로
2회의 최솟값 (`cli.measure` 와 같은 규칙).

| 설정 | 도구 수 | 기동 토큰 | 증분 |
|---|---|---|---|
| `{"mcpServers":{}}` | 0 | 12,934 | — |
| 측정용 stdio 서버 | 1 | 12,950 | **+16** |
| `npx -y @playwright/mcp@latest` | 24 | 13,302 | **+368** |

**서버당 고정비는 거의 없고 도구 하나당 ~15토큰이다** `[M]`. 두 측정이 서로를 확인한다
(16/1 · 368/24 = 15.3).

**기준선 절대값은 실행마다 흔들리지만 증분은 안 흔들린다** `[M]` — 재실행에서 기준선이
12,934 → 12,977 로 움직이는 동안 증분은 +16 · +368 로 같았다. 그래서 A/B 를 **한 번의
실행 안에서** 붙여야 한다. `jig budget` 을 두 번 돌려 빼는 방식은 안 된다 — 실행 간
드리프트(수백 토큰)가 재려는 값보다 크다.

### 왜 이렇게 싼가 — MCP 도구는 지연 로딩된다

같은 세션에 도구 이름을 물으면 playwright 도구 24개가 전부 **"지연 로딩 (ToolSearch 로
스키마 로드 후 호출 가능)"** 목록에 들어간다 `[M]`. 즉 기동 시점에 컨텍스트에 오르는 것은
**이름뿐이고 스키마·설명은 아니다.** 15토큰은 `mcp__playwright__browser_console_messages`
같은 이름 하나의 길이다.

그래서 "MCP 를 붙이면 도구 정의만 컨텍스트를 먹는다" 는 예전 판단은 **과대평가였다.**
비교 대상이 스킬인데, 스킬 설명은 기동 시점에 통째로 올라간다 — 스킬 하나가 평균
~73토큰이다 (`jig skills` 합계 2,491 / 34개). **MCP 서버 하나(24도구, 368토큰)가 스킬
5개와 같은 값이다.**

이 결과는 켜는 근거가 아니라 **값을 아는 것**이다. 도구 이름이 컨텍스트에 있으면 모델이
그것을 부를 후보로 본다는 문제는 토큰과 별개이고, 여기서 잰 것이 아니다 `[J]`.

## 2. `${VAR}` 확장

`--mcp-config` 파일에 `args` 와 `env` 양쪽으로 참조를 넣고, 서버 프로세스가 받은 값을
파일로 남겼다.

```json
"args": ["…/server.py", "--tok=${JIG_PROBE_SECRET}"],
"env":  {"PROBE_HEADER": "Bearer ${JIG_PROBE_SECRET}", "PROBE_PLAIN": "literal-value"}
```

서버가 본 것:

```json
{"argv": ["--tok=probe-secret-7734"],
 "env": {"PROBE_HEADER": "Bearer probe-secret-7734", "PROBE_PLAIN": "literal-value"}}
```

**`args` 와 `env` 둘 다 확장된다** `[M]`. `${VAR}` 안에서 접두·접미 문자열과 섞여도
(`Bearer ${…}`) 그대로 붙는다. 그래서 카탈로그는 비밀을 값으로 갖지 않고 참조만 실을 수
있다 — `posthog` 이 그렇게 등록돼 있다.

### 변수가 없으면 — 조용히 리터럴이 간다

같은 설정에서 이름만 미설정 변수로 바꿔 다시 돌렸다.

```json
{"argv": ["--tok=${JIG_PROBE_UNSET_XYZ}"],
 "env": {"PROBE_HEADER": "Bearer ${JIG_PROBE_UNSET_XYZ}", "PROBE_PLAIN": "lit"}}
```

`claude` 종료코드 0, stderr 없음, 서버는 정상 기동 `[M]`. **치환도 경고도 없이 리터럴
`${VAR}` 이 그대로 서버로 간다.**

이게 실제로 켜는 사람이 밟는 경로다. `posthog` 은 원격 서버라 이 문자열을
`Authorization` 헤더로 보내고 **401 을 받는다** — 화면에는 인증 문제로 보이지 `env` 를
안 넣었다는 신호로는 안 보인다. 그래서 그 항목의 `why` 에 변수 이름을 적어 둔다.

### 아직 안 잰 것

- 원격(`{"type":"http","url":…}`) 서버의 기동 비용. 여기서 잰 것은 stdio 둘뿐이다.
