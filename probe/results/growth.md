# 성장 곡선 실측 `[M:CC-SKILL-DESC-COST]`

- 대상: Claude Code 2.1.228 / macOS · 2026-08-12
- 방법: `hns growth 0 10 25 50` — 합성 스킬 N개짜리 플러그인을 만들어
  `--output-format json` 의 usage 로 기동 토큰을 잰다. 캐시 편차 때문에
  **2회 실행 후 최솟값**을 쓴다.
- 재현: `hns growth 0 10 25 50`

## 결과

| 스킬 수 | 기동 토큰 | 0개 대비 증가 | 스킬당 |
|---:|---:|---:|---:|
| 0 | 12,069 | — | — |
| 10 | 12,815 | +746 | 75 |
| 25 | 13,820 | +1,751 | 70 |
| 50 | 15,495 | +3,426 | 69 |

**선형이다.** 스킬 하나가 세션마다 항상 지는 비용은 **약 69–75 토큰**
(합성 스킬 설명 기준, 약 220자).

## 설명 길이가 유일한 레버다

같은 방법으로 잰 Claude Code **번들 스킬 11개는 1,776 토큰 = 스킬당 약 161 토큰**이었다.
합성 스킬의 2.3배다. 차이는 하나뿐 — **설명(description)이 길다.**

| 출처 | 스킬당 |
|---|---|
| 합성 스킬 (설명 약 220자) | ~69–75 |
| 번들 스킬 (설명이 길고 트리거 예시 포함) | ~161 |

→ **규칙: 스킬 설명은 짧게 쓴다.** 본문은 호출 시에만 로드되므로 얼마든 길어도 되지만,
설명은 매 세션 전원이 낸다. 설명 한 줄을 줄이는 것이 본문 100줄을 줄이는 것보다 값지다.

## 이 하네스에 주는 결론

스킬당 70(짧은 설명)~161(긴 설명) 토큰으로 외삽하면:

| 라이브러리 총 스킬 | 안 나눴을 때 | 나눴을 때 (역할당 8개) |
|---:|---:|---:|
| 25 | +1.8k ~ +4.0k | +0.6k ~ +1.3k |
| 50 | +3.4k ~ +8.1k | +0.6k ~ +1.3k |
| 100 | +6.9k ~ +16.1k | +0.6k ~ +1.3k |
| 200 | +13.8k ~ +32.2k | +0.6k ~ +1.3k |

25개까지는 나누든 말든 큰 차이가 없다. **50개를 넘어가면 갈린다.**
프로필 하나의 오버헤드가 213 토큰이므로 — 나누는 비용은 스킬 3개 값이다.

즉 이 설계의 값은 오늘이 아니라 **라이브러리가 50개를 넘는 시점**에 나온다.
지금 나눠 두는 게 맞다.

## 측정의 한계

- 합성 스킬 설명 길이 하나로만 쟀다. 실제 스킬은 더 길 것이다 → 위 범위의 위쪽을 보라.
- 캐시 상태에 따라 합산값이 크게 흔들린다. **콜드 런에서 93,118, 웜 런에서 14,193** 을
  같은 설정에서 관측했다. 그래서 최솟값을 쓴다. `[M]`
- MCP 비용은 아직 못 쟀다 `[?]` — `-p` 경로에 앱 커넥터가 안 붙는다.
  확인 방법: 인터랙티브 세션에서 `/context` 로 MCP 도구 정의 크기를 본다.
