# 프로필 전환

**로드된 스킬과 권한은 되돌릴 수 없다.** 전환은 새 프로세스에서만 성립한다.
그러니 이 스킬은 전환하는 척하지 않는다. 하는 일은 셋이다.

## 1. 완료 조건 점검

현재 프로필의 시스템 프롬프트 말미에 있는 **완료 정의**를 하나씩 확인한다.
실행 가능한 명령이면 **실제로 돌린다.** 통과·미통과를 항목별로 보고한다.

미완 항목이 있으면 전환을 권하지 말고 그것부터 처리하자고 말한다.

## 2. 산출물 확인

현재 프로필의 산출물 경로가 실제로 채워졌는지 읽어서 확인한다.
비어 있거나 자리표시자만 있으면 그렇게 보고한다.

그다음 `<프로젝트>/.harness/state.json` 을 갱신한다. **1의 판정 결과를 `done` 에
그대로 기록한다** — 이 기록을 다음 `jig <프로필>` 기동이 읽어서, 미충족이면 전진을
차단한다. 기록하지 않으면 게이트는 조용히 통과한다(기억 대행이지 강제가 아니다).

```json
{ "profile": "<현재>", "slug": "<작업 단위>", "next": "<요청된 다음 프로필>", "ts": "<ISO8601>",
  "done": { "passed": <통과 수>, "total": <전체 수>, "unmet": ["<미충족 항목의 짧은 서술>"] } }
```

`unmet` 의 문장은 차단 메시지에 그대로 노출되므로 한 줄로 짧게 쓴다.
디렉터리가 없으면 만든다. **쓴 뒤에는 되읽어 확인한다.**

## 3. 다음 명령 안내

마지막에 이 형식으로 출력한다:

```
✓ <현재> 단계 완료 조건: <통과 n>/<전체 n>
✓ 산출물: <경로> (<줄 수>줄)

다음 단계로 가려면 이 세션을 닫고 실행하세요:

    jig <다음 프로필>

(이유: 이미 로드된 스킬·권한은 이 프로세스에서 바뀌지 않습니다)
```

미완 항목이 남은 채 기록됐으면 그 사실도 말한다 — 다음 프로필 기동은 이 기록 때문에
차단되며, 되돌아와 마저 끝내거나 `JIG_GATE_BYPASS=1` 로 명시적으로 우회해야 한다.

프로필 이름을 모르면 `jig list` 를 안내한다.
