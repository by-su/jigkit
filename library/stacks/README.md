# 스택 정의

언어·기능별로 **어떤 도구를 어떤 표면으로 붙이는지**의 단일 진실이다. 아래 카탈로그 표와
`jig stack` 출력, 그리고 실제 배치 절차가 모두 이 yaml 들에서 나온다 — 문서와 동작을 따로
쓰면 어긋나기 때문이다(`adapters/commands.py` 가 생긴 것과 같은 이유).

```
python.yaml       언어 스택 — base(항상) + optional(선택)
typescript.yaml
common.yaml       언어 중립. base 가 비어 있고 create 가 없다
presets.yaml      조합에 이름과 alias 를 붙인다
templates/<id>/   apply 가 복사하는 설정 파일. 이미 있으면 덮지 않는다
```

## 표면 — 이 항목을 에이전트가 어떻게 잡는가

`surface` 가 이 카탈로그의 핵심이다. 같은 라이브러리라도 잡는 손잡이가 다르면 다르게 배치된다.

| surface | 뜻 | 어디로 가는가 |
|---|---|---|
| `mcp` | 업스트림이 MCP 서버를 출하한다 | 여기 있는 정의를 프로필이 id 로 바로 켠다. **자동으로 켜지지는 않는다** |
| `agents` | 업스트림이 서브에이전트 정의를 출하한다 | `init` 명령이 대상 프로젝트에 생성 (예: Playwright) |
| `hook` | 파일을 고친 직후 결정론적으로 돌아야 한다 | `.claude/hooks/jig-format` 의 분기 하나 |
| `gate` | 커밋 전에 막아야 한다 | `.claude/hooks/jig-gate` 의 분기 하나 |
| `library` | 에이전트 표면이 없다 | 설치만. **그 사실 자체가 카탈로그가 실어야 하는 정보다** |

`library` 를 "빠진 것"으로 읽지 않는다. Biome·Ruff 에 공식 MCP 가 없는 것은 방치가 아니라
CLI 가 이미 결정론적이라는 신호이고, 그래서 훅으로 간다.

한 도구가 표면을 둘 가지면 **id 를 둘로 쪼갠다** — `storybook`(library)/`storybook-mcp`(mcp),
`playwright-agents`(agents)/`playwright-mcp`(mcp), `docker`(library)/`docker-mcp`(mcp),
`semgrep`(gate)/`semgrep-mcp`(mcp). 하나가 기본이고 다른 하나는 골라 켜는 것이라는 판단도
각자의 `why` 에 산다.

`surface: mcp` 항목은 프로필의 `mcp:` 에 id 만 적으면 켜진다 — `library/mcp/` 에 파일이
없어도 된다. 그 디렉터리는 override 다(`library/mcp/README.md`).

## 항목 형식

```yaml
- id: ruff                     # 고유. 여러 스택이 같은 id 를 가리키면 한 번만 배치된다
  role: lint                   # 카탈로그의 "기능별" 축
  surface: hook
  install: "uv add --dev ruff" # 없으면 설치 단계를 건너뛴다
  init: "..."                  # 설치 후 한 번 돌리는 것 (prisma init, shadcn init …)
  detect: { dep: ruff }        # jig stack check 가 볼 것. dep | file | mcp
  template: pytest             # templates/pytest/ 를 복사
  hook:                        # surface: hook 일 때
    event: PostToolUse
    ext: [".py"]
    run: "uv run ruff format {file}"
  gate: { run: "uv run pyright" }        # surface: gate 일 때
  mcp: { command: npx, args: [...] }     # surface: mcp 일 때. 원격은 { type: http, url: ... }
  why: "근거. 등급을 붙인다 [D]/[M]/[J]/[?]"
```

`{file}` 은 훅이 받은 파일 경로로, `{dir}` 은 `create` 의 대상 디렉터리로 치환된다.

## 언어 파일

```yaml
name: python
create: "uv init {dir}"        # 새 프로젝트 스캐폴드. common.yaml 은 갖지 않는다
base: [...]                    # 이 언어면 거의 항상 참
optional:
  fastapi:
    create: "..."              # 프레임워크가 스캐폴더를 갖는 경우 언어 create 를 덮는다
    strips: [eslint]           # 스캐폴더가 깔아 놓는 것 중 base 와 충돌하는 것
    requires: [fastapi]        # 다른 optional 키에 의존할 때
    verify: [...]
    items: [...]
conflicts: [[ruff, black]]     # 한쪽은 우리 id, 다른 쪽은 프로젝트에 이미 있을 수 있는 도구
verify: [...]                  # 조합 전체의 마지막 검사
```

같은 `role` 에 `gate` 표면이 둘 들어오는 것은 `conflicts` 에 적지 않아도 막힌다 — 서로 다른
규칙으로 같은 파일을 판정하는 게이트 둘은 우회 습관을 만든다.

## 항목을 지우면 배치된 분기도 은퇴한다

훅·게이트 분기는 대상 프로젝트의 디스패처 안에 **id 로** 산다. `jig stack apply` 는 거기서
발견한 분기를 세 갈래로 가른다 — 판정 근거는 이 카탈로그이고, 프로젝트별 적용 기록은 없다:

| 분기 | 처리 |
|---|---|
| 이번 조합에 있다 | 이번 정의로 갱신 |
| 이번 조합엔 없지만 카탈로그에 있다 | **유지** (다른 스택이 쓴다). 단 카탈로그 정의로 다시 렌더한다 |
| 카탈로그에 없다 | **은퇴** — 분기를 지우고 무엇을 지웠는지 출력한다 |

그래서 여기서 항목을 지우면 이미 적용된 프로젝트에서도 다음 `apply` 에 사라진다. 다시 렌더하는
쪽이 있어서 디스패처는 `(카탈로그, 살아 있는 id 집합)` 의 함수다 — 한 스택만 apply 한
프로젝트에 다른 스택의 옛 명령이 남지 않는다. `jig stack check` 는 apply 없이도 남아 있는
분기를 짚는다.

**여기서 지우는 것과 "이 프로젝트에서만 빼는 것"은 다르다.** 후자는 id 가 카탈로그에 그대로
있으므로 유지된다 — 별도 동작이 필요하고 아직 없다.

## 템플릿

`templates/<id>/` **밑의 모든 파일이 대상 프로젝트로 그대로 복사된다** (이미 있으면 건드리지
않는다). 그러니 여기에는 프로젝트에 들어가야 할 파일만 둔다 — 템플릿을 설명하는 문서를 두면
그것까지 남의 프로젝트에 `README.md` 로 복사된다. 설명은 이 문서에 적는다.

지금 있는 것:

- `biome/biome.json` — `rules.preset: "recommended"` 를 쓴다(`rules.recommended: true` 는
  Biome 2.5 에서 deprecated `[M]`). **`style.useImportType` 을 끈다** — 켜 두면
  `biome check --write` 가 `import { AppService }` 를 `import type` 으로 바꿔서 **NestJS 의
  의존성 주입이 런타임에 깨진다** `[M]`. 타입 검사는 통과하고 테스트에서만 터진다
  (`probe/results/stack-scaffold.md`).
- `vitest/vitest.config.ts` — `include` 를 `src/**`·`test/**` 의 `*.test.*` 로 좁힌다.
  `*.spec.ts` 는 다른 러너 것이다 (Playwright 의 `seed.spec.ts`, Nest 의 Jest 스펙).
- `pytest/tests/test_smoke.py` · `vitest/src/smoke.test.ts` — 스모크 테스트 한 개.
  없으면 갓 만든 프로젝트에서 테스트 단계가 신호를 못 준다.
