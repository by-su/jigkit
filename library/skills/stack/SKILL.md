# 스택 세팅

**조합을 추론하지 않는다.** 어떤 말이 어떤 조합으로 가는지는 `library/stacks/presets.yaml` 의
`aliases` 에 있다. 매번 판단하면 같은 요청이 매번 다르게 세팅된다.

## 1. 조합을 조회한다

```bash
jig stack show <요청에 나온 말>     # fastapi · nextjs · expo · storybook …
```

이름이 안 잡히면 `jig stack list` 로 무엇이 있는지 본 뒤 `--with` 로 조립하고,
**프리셋에 없는 조합을 만들었다는 사실을 말한다.** 기존 프로젝트에 추가하는 경우라면
`pyproject.toml`·`package.json`·`app.json` 을 먼저 읽고 언어를 확인한다.

## 2. 사람에게 보이고 동의를 받는다

`jig stack show` 출력이 그 자리다 — 무엇이 설치되고 어떤 훅·게이트·MCP 가 붙는지 나온다.
동의 없이 3번으로 넘어가지 않는다. 남의 저장소를 쓰는 일이다.

## 3. 새 프로젝트면 계획대로 실행한다

```bash
jig stack show <조합> --plan <디렉터리>
```

출력된 명령을 **순서대로** 돌린다. 순서는 되돌리기 어려운 구간이라 바꾸지 않는다:
`create` → `strip` → `install` → `init` → `apply` → `normalize` → `verify`.

각 줄은 스스로 `cd` 를 포함하므로 한 줄씩 따로 실행해도 된다 — **줄에서 `cd` 를 떼지 않는다.**
떼면 셸이 줄마다 새로 뜨는 실행기에서 install 이 엉뚱한 디렉터리로 간다.

- **인자를 창작하지 않는다.** 스캐폴더 인자는 실측해서 데이터에 적힌 것이다
  (`probe/results/stack-scaffold.md`). 바꿔야 했으면 무엇을 왜 바꿨는지 말하고,
  그게 반복될 일이면 `library/stacks/*.yaml` 을 고치자고 제안한다.
- 대화형 프롬프트·네트워크 실패·패키지 매니저 없음은 여기서 판단한다. 그게 이 스킬이
  파이썬 실행기 대신 존재하는 이유다.
- 훅 JSON·설정 파일·MCP 정의는 **직접 쓰지 않는다.** `apply` 단계가 한다 — 손으로 쓰면
  멱등성이 깨지고 다른 스택의 분기가 지워진다 (실측: `probe/results/stack-hooks.md`).

**기존 프로젝트에 추가하는 경우에도 `--plan` 을 쓴다.** `apply` 는 훅·설정·MCP 정의만 쓰고
**의존성을 설치하지 않는다** — `apply` 만 돌리면 훅과 게이트가 깔리지 않은 도구를 가리키고,
매 편집마다 stderr 만 나온다. `--plan` 은 대상이 비어 있지 않으면 `create`·`strip` 을 알아서
빼고 `install`·`init`·`apply`·`normalize`·`verify` 만 낸다. 먼저 `--apply` 없이 보여준다.

## 4. 결과를 대조한다

```bash
jig stack check <조합> <디렉터리>
```

빈 목록이 나와야 끝난다. 어긋난 항목이 있으면 **그것만** 처리한다.
이 명령이 마지막에 있는 이유는, 다른 길로 갔더라도 결과에서 드러나게 하기 위해서다.

## 하지 않는 것

- **MCP 를 프로필에 켜지 않는다.** 카탈로그에 있는 id 는 프로필의 `mcp:` 에 적기만 하면
  켜지지만, 그 줄은 사람이 넣는다 — 기동 토큰이 조용히 늘어나면 안 된다.
- 카탈로그에 없는 도구를 임의로 추가하지 않는다. 필요하면 `library/stacks/` 에 항목을
  추가하자고 제안한다 (`why` 에 근거와 등급이 필요하다).
