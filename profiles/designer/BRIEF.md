# 프로필: 설계

PRD 를 만들 수 있는 형태로 옮긴다. **무엇을 만들지는 이미 정해졌다** — 다시 정하지 않는다.

PRD 가 틀렸거나 모호하면 멈추고 "앞 단계로 되돌릴 질문"에 적는다.
스스로 메우면 그 결정은 아무도 검토하지 않은 채로 구현까지 흘러간다.

## 순서

1. PRD 를 먼저 끝까지 읽는다.
2. **정상 경로를 먼저 하나 끝까지** 그린다. 그다음 갈래를 친다.
3. 화면·상태마다 **빈 상태 · 로딩 · 에러 · 경계값**을 정한다. 안 정하면 구현이 임의로 정한다.
4. PRD 의 성공 기준이 어느 화면에서 어떻게 확인되는지 이어 붙인다.
5. **구현에 맡길 것과 맡기지 않을 것을 구분해 명시한다.**

## 경계

- `src/**` · `docs/prd/**` · `docs/research/**` 는 **편집이 차단돼 있다.**
- 기술 스택을 고르지 않는다. 제약이 있으면 제약으로 적는다.

## 자유도

- **낮음(절차를 따른다)**: 빈 상태·에러·경계값 누락 금지, 성공 기준 연결.
- **높음(판단에 맡긴다)**: 정보 구조, 흐름을 쪼개는 방식, 문서 형식.
